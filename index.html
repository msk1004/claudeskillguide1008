Claude Codeを使っている方なら、どなたでも導入できる2つの「スキル」をご紹介します。各スキルについて、まず「何ができるか」、次に「どう作るか」の順に解説します。

はじめに：「スキル」とは

スキルとは、Claude Codeに覚えさせておく「作業手順書」です。1つのフォルダに SKILL.md というテキストファイルを置くだけで完成し、以後は「/スキル名」と入力する（または決まった言葉で話しかける）と、Claudeが手順書どおりに作業します。

置き場所（どちらか）
  • 自分のPC全体で使う：~/.claude/skills/スキル名/SKILL.md（Windowsは C:\Users\ユーザー名\.claude\skills\スキル名\SKILL.md）
  • 特定プロジェクトだけで使う：プロジェクト/.claude/skills/スキル名/SKILL.md

この資料では、どの広告代理店・制作会社でも使えるよう、自社名・取引先名を含まない汎用版で手順を解説します。

この資料は、Claude Codeに読み込ませると、Claudeが質問しながら導入を進めてくれるように作ってあります。手作業でコピーする必要はありません。

① GitHub Pages公開スキル

資料を1コマンドでURL化

何ができる？

Claudeが作った提案書・レポートなどのHTML資料を、そのままインターネット上のURLで公開します。ファイルをメールに添付する代わりに、URLを送るだけで先方が見られます。

STEP 1公開したいHTMLを特定
STEP 2資料の内容から公開名を自動命名
STEP 3GitHubに保管用フォルダ（リポジトリ）を作成
STEP 4GitHub Pagesで公開
完了公開URLを返す

使いどころ

例1　クライアントへの提案書をURLで共有（添付容量・文字化け・バージョン違いの心配なし）
例2　社内向けのレポート・調査まとめを、チームにURLで一斉共有
例3　スマホで見せたい企画書（URLを開くだけ・修正したら同じURLが更新される）

公開した資料の実例

実際にこのスキルで公開した提案書です。URLを送るだけで、先方がスマホやPCですぐ閲覧できます。
https://msk1004.github.io/tobishitieup1007/

使い方（導入後）

/gitpages ファイルパス(任意) リポジトリ名(任意)

省略すると、直前の会話で作ったHTMLが対象になります。リポジトリ名は、実行前にClaudeが提案して確認してくれます。

ご注意：GitHub Pages（無料）はURLを知っている人なら誰でも見られる公開設定です。社外秘情報・他社との取引条件が入った資料は公開しないでください。また公開名にクライアント名を入れる場合は、そのクライアント本人に共有する用途に限りましょう。

実装方法（所要 約15分）

GitHubアカウントを作る

github.com/signup から無料登録します。決めたユーザー名は後で使うのでメモしてください。

GitHub CLI（gh）をインストール

Claudeが代わりにGitHubを操作するための公式ツールです。

Windows（PowerShell）

winget install --id GitHub.cli

Mac（ターミナル）

brew install gh

インストール後、ターミナルを一度閉じて開き直してください。

GitHubにログイン（初回のみ）

gh auth login

質問が出たら、矢印キーとEnterで GitHub.com → HTTPS → Yes → Login with a web browser の順に選びます。画面に表示される8桁のコードをブラウザに入力すれば完了です。

確認：gh auth status と入力して「Logged in」と出ればOKです。

スキルのファイルを作る

次のフォルダを作り、中に SKILL.md という名前で下記の内容を保存します。「あなたのGitHubユーザー名」の部分だけ書き換えてください。

~/.claude/skills/gitpages/SKILL.md

ヒント：Claude Codeに「上の場所に、次の内容でSKILL.mdを作って」と貼り付けて頼めば、フォルダ作成から保存まで代行してくれます。

---
name: gitpages
description: HTMLで作成した資料を、内容から命名した新規GitHubリポジトリでGitHub Pages公開し、公開URLを返す。「公開して」「URLにして」「gitpages」と言われたら使う。
---

# GitHub Pages公開ワークフロー

## 前提
- GitHubユーザー名: あなたのGitHubユーザー名
- 公開URL形式: https://あなたのGitHubユーザー名.github.io/{リポジトリ名}/
- GitHub CLI(gh)が認証済みであること

## 使い方
/gitpages [ファイルパス(任意)] [リポジトリ名(任意)]
- ファイルパス省略時は、直近の会話で作成した.htmlを対象にする
- リポジトリ名を指定した場合は自動命名をスキップする

## Step 0: 認証確認
`gh auth status` を実行。未ログインなら、ユーザーに `gh auth login` の実行を案内し、完了報告を待つ（対話操作のため代行不可）。

## Step 1: 対象ファイルの特定
対象HTMLと、それが相対パスで参照するCSS・JS・画像を収集する。不明な場合はユーザーに確認する。

## Step 2: リポジトリ名の自動命名
資料の内容(宛先・資料種別・作成日)から、半角英数字・小文字のみのスラッグを作る。
形式: {宛先や案件の英語スラッグ}{資料種別の英単語}{MMDD}  例: abcproposal0814
`gh repo view {名前}` で既存確認し、重複時は末尾に v2, v3 を付ける。
実行前に、決めた名前をユーザーに提示して確認を取る。

## Step 3: 公開用フォルダの準備
作業用フォルダに対象HTMLを index.html としてコピー（アセットは相対パス構造を維持）し、
git init → main ブランチ → add → commit する。

## Step 4: 作成・push・公開
gh repo create {リポジトリ名} --public --source=. --remote=origin --push
gh api -X POST "repos/あなたのGitHubユーザー名/{リポジトリ名}/pages" -f "source[branch]=main" -f "source[path]=/"
※権限設定でブロックされた場合は、作業フォルダの場所と上記2コマンドをユーザーに案内し、実行完了を待つ。無断でブロックを回避しない。

## Step 5: 公開確認
gh api repos/あなたのGitHubユーザー名/{リポジトリ名}/pages で "status":"built" を確認する。"building" の場合は少し待って再確認。

## Step 6: 完了報告
公開URL・リポジトリURL・対象ファイルパスを提示する。

## 注意事項
- リポジトリは public で作成する（GitHub Pages無料利用のため）
- 公開前に、社外秘情報・他社の取引条件・個人情報が資料に含まれていないかユーザーに確認を促す
- 公開は外部への発信行為のため、必ずユーザー確認を経てから実行する

Claude Codeを再起動して試す

Claude Codeを開き直し、まず練習用の簡単なHTMLで試します。

「こんにちは」とだけ表示するHTMLを作って、/gitpages で公開して

リポジトリ名の確認 → 公開 → URLが返ってくれば成功です。公開反映には1〜2分かかることがあります。

② Notion議事録同期スキル

議事録を自動で整理・保存

何ができる？

Notion（AI議事録やミーティングノート）に溜まった議事録を、前回の同期以降の新しい分だけ取得し、パソコン内のフォルダへ「社内／クライアント別／プロジェクト別」に自動で振り分けて保存します。「議事録を同期して」と話しかけるだけです。

STEP 1前回同期した日付以降の議事録をNotionから取得
STEP 2タイトル・親ページ名からカテゴリを自動判定
STEP 3振り分け結果を表で提示 → 確認
STEP 4日付つきファイルで一括保存
完了同期日を更新（次回は差分のみ）

使いどころ

例1　週明けに「先週の打合せ」をまとめて取り込み、案件フォルダに整理
例2　過去の議事録をフォルダ単位で保管し、提案書づくりのときにClaudeに読み込ませる
例3　アクションアイテム（担当者・期限）だけを一覧で確認

保存されるもの・フォルダ構成

議事録/
├── 社内/
│   └── 20261006_週次チームMTG.md
├── クライアント/
│   └── ABC商事/
│       └── 20261005_ABC商事_提案打合せ.md
└── プロジェクト/
    └── 新商品PR/
        └── 20261004_新商品PR_キックオフ.md

ファイルには「日時・カテゴリ・セクション別の要点・アクションアイテム（担当者・期限）」を保存します。文字起こし全文は保存しません（要約のみ）。

実装方法（所要 約10分）

Notionに議事録を溜める環境を用意

NotionのAIミーティングノート機能、または手動で作った議事録ページなど、Notion上に議事録があればOKです。親ページ名を「取引先名」にしておくと、自動振り分けの精度が上がります。

Claude CodeにNotionを接続（MCP連携）

ターミナルで次のコマンドを実行します。

claude mcp add --transport http notion https://mcp.notion.com/mcp

Claude Codeを起動し、チャットに /mcp と入力 → notion を選んで認証（ブラウザでNotionにログインし、「許可」を押す）します。「connected」と表示されれば完了です。

デスクトップアプリの場合は、設定のコネクタ（Connectors）からNotionを追加しても同じです。

スキルのファイルを作る

次の場所に、下記の内容で SKILL.md を保存します。

~/.claude/skills/notion-sync/SKILL.md

ヒント：ここでも「次の内容でSKILL.mdを作って」とClaudeに貼り付ければ代行してくれます。

---
name: notion-sync
description: Notionの議事録を取得し、ローカルのフォルダへカテゴリ別に自動振り分けして保存する。「議事録を同期して」「Notionを同期」と言われたら使う。
---

# Notion議事録ローカル同期

## 設定ファイル
このSKILL.mdと同じフォルダの config.json を使う。無ければ「初回設定」を行って作成する。

## 初回設定（config.jsonが無い場合のみ）
次を順にユーザーへ質問し、config.json を作る。
1. 議事録の保存先フォルダ（無ければ作成）
2. 使うカテゴリ（社内 / クライアント別 / プロジェクト別・複数可）
3. 「社内」と判断するキーワード（例: 週次, 全体会議, 部内）
4. 既知のクライアント名・プロジェクト名（省略可）
5. どれにも当てはまらない議事録の扱い（クライアント別 / プロジェクト別 / 毎回確認）

config.json の形式:
{
  "base_dir": "保存先フォルダのパス",
  "last_synced_date": "2020-01-01",
  "categories": {
    "社内": {"enabled": true, "folder": "社内", "keywords": []},
    "クライアント": {"enabled": true, "folder": "クライアント", "clients": []},
    "プロジェクト": {"enabled": false, "folder": "プロジェクト", "projects": []}
  },
  "default_category": "クライアント"
}

## 同期の手順
1. config.json を読み、last_synced_date を取得する。
2. Notion MCPの notion-query-meeting-notes で、created_time が last_synced_date 以降の議事録を取得する。
   - 「date_is_after」はエラーになるため「date_is_on_or_after」を使い、取得後に last_synced_date と同日のものは除外する。
   - 0件なら「新しい議事録はありません」と報告して終了。
3. 各議事録を notion-fetch で取得（並行実行）。親ページ名・本文のセクション・アクションアイテムを使う。文字起こし全文は保存しない。
4. 次の優先順位でカテゴリを判定する。
   ① 親ページ名またはタイトルに「社内キーワード」を含む → 社内
   ② 親ページ名が clients のいずれかに部分一致 → クライアント/{会社名}
   ③ 親ページ名またはタイトルが projects のいずれかに部分一致 → プロジェクト/{PJ名}
   ④ 該当なし → default_category に従う（「手動」なら未分類として残す）
   ※親ページ名の末尾の「様」「御中」「さん」や記号は除いてから照合する。
5. 振り分け結果を表（番号・日付・タイトル・カテゴリ・保存先）で提示し、ユーザーの確認を取る。修正指示があれば反映して再提示。
6. 承認後、フォルダを作成し、次の形式で保存する。
   - ファイル名: YYYYMMDD_{サブフォルダ名}_{タイトル}.md（社内はサブフォルダ名を省略）
   - タイトル中の「@昨日」などの日付メンションは除去
   - 同名ファイルがあれば上書きせず末尾に _2, _3 を付ける
   - 内容: タイトル / 日時 / カテゴリ / Notion親ページ名 / セクション別の箇条書き / アクションアイテム（- [ ] 担当者：内容（期限：YYYY-MM-DD））
7. 保存後、config.json の last_synced_date を、処理した中で最も新しい議事録の日付に更新する。
8. 処理件数と保存先の一覧を報告する。新規作成したフォルダは「新規」と明記する。

## 注意
- Notionへの書き込み・削除は行わない（読み取り専用）
- config.json が壊れている場合は、読めない旨を伝えて設定のリセットを確認する

Claude Codeを再起動して初回実行

チャットで次のように話しかけます。

議事録を同期して

初回は設定ウィザードが始まり、保存先フォルダ・社内キーワードなどを質問されます。答えるだけで設定が保存され、2回目以降は質問なしで同期が走ります。

運用のコツ

  • 週1回など、決まったタイミングで「議事録を同期して」と話しかける
  • 振り分けが違っていたら確認の表で「#2 クライアント XYZ社」のように直す（その内容を config.json のクライアント一覧に追記しておくと、次回から自動で正しく振り分けられます）
  • 設定を作り直したいときは config.json を削除して再実行

つまずきやすい点

症状対処
/gitpages が反応しないSKILL.mdの場所（skills/gitpages/SKILL.md）と、先頭の --- で囲んだ name・description を確認。Claude Codeを再起動する
公開URLが「404」になる公開反映に1〜2分かかります。少し待ってから再読み込みしてください
リポジトリ作成が権限設定でブロックされた公開行為のため確認が入ることがあります。Claudeが案内するコマンドを、ご自身でターミナルに貼り付けて実行してください
gh が見つからないインストール後にターミナルを開き直す。それでも出ない場合はPCを再起動
Notionの議事録が取得できない/mcp でnotionが connected か確認。未認証なら認証し直す。対象ページがNotion側で連携に共有されているかも確認
「新しい議事録はありません」と出るconfig.json の last_synced_date が未来日になっていないか確認
ほかの業務にも応用できます
  • スキルは「いつもの手順を文章で書く」だけで作れます。この2つを土台に、見積書づくり・週報のまとめ・クライアント情報のリサーチなど、毎回同じ流れの作業をスキル化すると効果的です。
  • 「いつもやっている手順をスキルにしたい」とClaudeに相談すると、SKILL.mdの下書きを作ってくれます。

Claude向け導入ガイド

この章は、この資料を読み込んだClaude Code向けの指示です。人が読む必要はありません。ユーザーから「この資料を読んで導入して」と依頼された場合のみ、以下に従ってください。

目的：本資料の2つのスキル（①gitpages ②notion-sync）を、ユーザーのPCに導入する。ユーザーはClaude Codeの利用者だが、GitHub・Notion・ターミナル操作に不慣れな可能性がある。専門用語を避け、1回の質問は1〜2点にとどめること。

進め方

  1. ヒアリング：次を順に質問する。
    • 導入したいスキル（①のみ／②のみ／両方）
    • OS（Windows／Mac）
    • ①の場合：GitHubアカウントの有無とユーザー名、ghがインストール・ログイン済みか（gh --version、gh auth statusで確認してよい）
    • ②の場合：Notionに議事録があるか、Notion MCPが接続済みか、議事録の保存先フォルダ、自社内会議を判別するキーワード、主なクライアント名／プロジェクト名（任意）
  2. 事前準備の案内：未導入の項目（GitHubアカウント作成、ghインストール、gh auth login、claude mcp add --transport http notion https://mcp.notion.com/mcpと/mcpでの認証）は、本資料の各「実装方法」に沿って案内する。ブラウザ認証やgh auth loginなど対話操作はユーザー自身に実行してもらい、完了報告を待つ。パスワード・トークンをチャットで受け取ってはならない。
  3. SKILL.mdの作成：本資料内の該当SKILL.md全文（各「スキルのファイルを作る」のコードブロック）を、~/.claude/skills/gitpages/SKILL.md・~/.claude/skills/notion-sync/SKILL.mdに保存する。①はヒアリングしたGitHubユーザー名で「あなたのGitHubユーザー名」を全て置換する。②はヒアリング結果から同フォルダにconfig.jsonを作成してよい（作成前に内容をユーザーに見せて確認）。既存の同名ファイルがある場合は上書きせず、ユーザーに確認する。
  4. 試運転：Claude Codeの再起動を案内する。①は「こんにちは」だけのHTMLを作って公開する練習を、②は議事録の同期を提案する。公開・外部書き込みなど外部への発信を伴う操作は、実行前にユーザーの承認を得る。
  5. 完了報告：導入したスキル、保存場所、使い方（/gitpages、「議事録を同期して」）を簡潔に伝える。

守ること

  • 日本語・丁寧で簡潔な言葉で案内する。
  • GitHub Pagesは誰でも閲覧できる公開設定である点を、初回公開前に必ず説明する。
  • Notionは読み取りのみ。Notion側の内容を書き換えない。
  • つまずいた場合は、本資料の「つまずきやすい点」の表を参照して対処する。
